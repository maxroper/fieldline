# Working on Fieldline

Read `docs/AI-HANDOFF.md` before changing anything. It explains the product, the three faces of the app (office, tech phone, customer), how a request flows, and where every kind of code lives.

## Commands

```bash
npm run dev          # API on 8787, web on 5173 (web proxies /api to the API)
npm run typecheck    # must pass before you say a change is done
npm test             # shared business rules
npm run db:generate  # after editing packages/db/src/schema/*.ts
npm run db:reset     # wipe local data and reseed
npm run build:demo   # the static demo (API + database inside the browser); published by GitHub Pages
```

The database is PGlite in `./data/pglite` unless `DATABASE_URL` is set. One process at a time can hold it open: stop the API before running `db:reset` or `db:seed` by hand.

## Rules that keep the codebase coherent

- **Business rules live in `packages/shared`.** Billing math, timesheet rules, quote totals, visit scheduling. The API and the web app both import them; neither reimplements them. Add a test when you change one.
- **Every table with `org_id` is under row-level security.** Request handlers run inside `withOrg(...)` through `scoped(conn)` in `apps/api/src/db.ts`. Never query outside it from a request. `withBypass` is only for sign-in, seeds and the public token routes.
- **Validate at the edge with the zod schemas in `packages/shared/src/schemas.ts`.** Routes call `parse(schema, body)`. Do not hand-validate in a route and do not trust the client.
- **One statement per `db.execute`.** PGlite rejects multi-command prepared statements. See `packages/db/src/rls.ts` for the pattern.
- **Work orders carry a `version`.** PATCH and status changes send it back; the API answers 409 on a mismatch. Keep that on any new editable record that two people can touch.
- **Dates are company days.** `companyDay()` and `companyMinute()` in `packages/shared/src/time.ts` use the org timezone. Store instants as ISO strings in `timestamptz` columns and days as `YYYY-MM-DD`.
- **Screens read through TanStack Query and write through `useAction`** (`apps/web/src/app/queries.ts`). It invalidates and toasts for you. Do not reach for local state to cache server data.
- **Styling is the design system in `apps/web/src/design/fieldline.css`** plus the React wrappers in `design/components.tsx`. No CSS framework, no inline color literals; use the tokens and the state color language in `docs/DESIGN-SYSTEM.md`.
- **Route files are the router.** `apps/web/src/routes/` is file-based (TanStack Router). `routeTree.gen.ts` is generated by the Vite plugin; never edit it. A segment with a trailing underscore (`work-orders.$id_.complete.tsx`) opts out of nesting.
- **Keep the three faces separate.** Office screens under `routes/_office/`, phone screens under `routes/tech/`, customer pages at `routes/t.$token.tsx` and `routes/portal.$token.tsx`. Office roles can preview a tech's phone with `/tech?as=<techId>`.
- **The API runs in two places.** On Node (`apps/api/src/index.ts`) and inside the browser for the static demo (`apps/api/src/demo.ts`). Keep `node:` imports out of `app.ts`, the routes, `auth.ts`, `storage.ts` and `env.ts`; node-only code goes in `index.ts`, `storage-node.ts` and `packages/db/src/client.ts`. After a schema change run `npm run db:generate` and commit the regenerated `packages/db/src/migrations.generated.ts`. `npm run build:demo` must still build.
- **Integrations are adapters.** Twilio, Stripe, QuickBooks, Maps and Clerk are behind small functions that fall back to a demo mode when keys are missing. Add a provider by extending the adapter, not by scattering `fetch` calls.

## When you finish a change

1. `npm run typecheck` and `npm test` pass.
2. The screen or endpoint was exercised against the seed data (sign in as James Reynolds for the office, Elena Cruz for a tech).
3. If the data model changed: a migration exists, the seed still runs, and `docs/DATA-MODEL.md` reflects it.
4. If a product rule changed: `docs/FEATURES.md` or `docs/DECISIONS.md` says so.

Commit messages describe the change in plain words and end with the attribution line the environment asks for.
