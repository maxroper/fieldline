# Fieldline data model and architecture (as found, Oct 2026)

# Fieldline — Data Model & Architecture Summary

Scope read: lib/types.ts (1,037 lines), lib/store.tsx (4,531 lines, all chunks), billing.ts, quote.ts, po.ts, inventory.ts, timesheet.ts, visits.ts, scopes.ts, vendors.ts, seed.ts, demo.ts, pdf.ts, xlsx.ts, app/layout.tsx, app/page.tsx, next.config.mjs, package.json, tsconfig.json, README.md, .cursorrules. components/FieldlineApp.tsx (10,511 lines / 556 KB) was not read per instructions. Stack: Next 14.2 static export (`output: "export"`), React 18.3, TS 5.5 strict, zero runtime deps beyond next/react.

## 1. Entities (lib/types.ts)

Root `Db` (types.ts:955-979) is one JSON document of arrays: orgs, teams, users, customers, sites, equipment, workOrders, notes, timeEntries, photos, quotes, scopeTemplates, purchaseOrders, warehouses?, inventoryCategories?, inventoryTxns?, hourChanges, callNoteEdits, techNotices, fieldChanges?, recordChanges?, timesheets, bills?.

- **Org** (98-110): id, name, city, quotePage (CompanyQuotePage: from/terms/signature), costs (CompanyCosts 36-72: costRates/nonContractRates/contractRates as HourlyRate rows; nonContractMargin/contractMargin as MarkupBand {upTo, divisor}; miscPercent, vehicleAmount, vehicleHours, materialMarkup, salesTaxPercent, rateSource manual|erp; legacy journeymanRate/apprenticeRate/driverRate mirrors), billTravelSeparately, vendors[] (Vendor embedded: name, city, phone, email).
- **Team** (112): orgId, name. **User** (118-143): orgId, role, title, phone, teamId (techs), homeTeamId (office), offDates[], shiftHours, canEditCustomers?, canBill? (per-user permission overrides).
- **Customer** (146-169, bill-to parent): orgId, name, phone, email, billingAddress, apContactName/Phone, billingRate and creditLimit (free-text strings), contract, accountManagerId→User(office), taxExempt, taxExemptNumber, invoiceDelivery, invoiceEmails[].
- **Site** (173-205): orgId, customerId→Customer, name, address, city, contact, contactPhone, accessNotes, defaultTechId/primaryTechId (kept in sync by hand), backupTechId, taxRate override, invoiceDelivery/invoiceEmails overrides, pmContract (PmContract: billingMethod pre_billed|on_demand, visitAmount). This is the only "agreement" record.
- **Equipment** (224-246): orgId, siteId, tag, kind, make, model, serial, tons, refrigerant (string), locationNote, source, stage, proposalId (points to a non-existent Proposal entity), nameplatePhoto, unitPhotos[] (base64 dataUrls).
- **WorkOrder** (285-368): orgId, number (job #, shared by return visits), trip (visit index), visitHigh, customerId, siteId, equipmentId, siteText, title, description, callType, billingType tm|nte|quoted, nteAmount, quotedAmount/contractAmount/estimate (mirrors), materialBudget, laborBudgetHours/totalHours (mirrors), laborBudget, priority, needReturn/waitingOnParts/warranty booleans, status, assignedTechId (lead), suggestedTechId, helpers[] (HelperAssignment: techId, scheduledFor, startMinute, allocatedHours, visit, techDone, techStatus, returnNote, signatureData, workPerformed, signerName), days[] (DayAssignment), scheduledFor (YYYY-MM-DD), startMinute (minutes from midnight), allocatedHours, dispatchNote, workPerformed, signerName, signatureData, followUp (FollowUp: reason, date, note, part, expectedDate), callerName/Phone, unitNumber, customerPo, signatureRequired, techDone, techStatus, techReturnNote, truckParts[] (TruckPart: description, quantity, unitCost, categoryId, inventoryTxnId, addedByUserId, addedAt, warehouseId). A return visit is a *new* WorkOrder row with the same number and a higher trip (store.tsx:3788-3854).
- **Note** (546), **TimeEntry** (690: woId, techId, hours, laborType, date, visit, kind labor|travel, startedAt, arrivedAt, stoppedAt, equipmentId), **Photo** (711: woId, caption, dataUrl, visit, equipmentId) — none carry orgId.
- **Timesheet** (659-688): orgId, techId, date, erpId, lines[] (TimesheetLine: timeEntryId, woId, visit, workOrder label, kind travel|labor|meal|rest|meal_premium|rest_premium, startedAt, stoppedAt, hours, edited, rate, arrivedAt, resume[]), closedAt, missedBreak/missedMeal/missedFirstMeal/missedSecondMeal, mealReason, mealReasonNote, breakReview {status, comment, reviewerId, reviewedAt}, changes[] (TimesheetChange).
- **Quote** (775-840): orgId, number, customerId, siteId, contactName/Phone, reason, problemText, sourceWorkOrderId, title (=scope), equipmentId, scopeTemplateId, scopeDraft, laborLines[], hours + journeyman/apprentice/driverHours, journeyman/apprentice/driverRate, laborRate (legacy), lines[] (QuoteLine: description, quantity, cost), vehicleCharge/miscCharge (legacy), markupPercent, price, files[] (QuoteFile dataUrl), status, sentAt/approvedAt/declinedAt, lossReason, lossNote, followUpDate, followUpKind, workOrderId (created on approve), erpId, visit. **ScopeTemplate** (762): orgId, name, scope, laborLines[], hours.
- **PurchaseOrder** (877-917): orgId, number, erpId, workOrderId, equipmentId, visit, vendor (name string — no FK), siteId, shipTo work_order|inventory, warehouseId, lines[] (PoLine: description, quantity, unitCost, receivedQty, categoryId, inventoryPostedCost, receivedOn, receivedById), lumpSum, lumpSumAmount, lumpSumAt, remindAt, status, orderedAt, expectedDate, receivedAt, receivedById, vendor invoiceNumber/Date/Amount, files[] (PoFile), draft.
- **Warehouse** (920: orgId, name, kind main|vehicle, techId, active), **InventoryCategory** (930: dollar bucket, "no parts list under a category"), **InventoryTxn** (940: orgId, warehouseId, categoryId, signed dollar amount, kind, woId, poId, description, userId, date).
- **Bill** (437-481, 1:1 with WorkOrder): orgId, workOrderId, erpId, billedAt, invoiceNumber, materialMode/laborMode itemized|one, material/labor/travelDescription, hideHourlyRate, descriptions[], taxableAmount, taxRate, salesTax, accruedUseTax, erpTaxExported, original (BillSnapshot), revisions[] (InvoiceRevision: rev, at, userId, reason, snapshot, invoice), credits[] (CreditMemo: number, at, userId, amount, reason, note, lineIds), deliveries[] (InvoiceDeliveryRecord: method, at, userId, emails), frozen/originalInvoice (FrozenInvoice: kind tm|fixed|quoted, lines/detail FrozenLine[], totals, taxKind, nteAmount, travelSeparate).
- **Audit/log rows**: HourChange (557), CallNoteEdit (568), FieldChange (604, field enum notes|problem|start|dispatch|date|hours|tech) — no orgId; RecordChange (591, orgId, customer/site field diffs); TechNotice (577, orgId, techId, woId, kind assignment|updated, readAt).

**Multi-tenancy coverage**: orgId is present on all top-level rows except Note, TimeEntry, Photo, HourChange, CallNoteEdit, FieldChange (reachable only via woId). Vendors are embedded per Org. Enforcement in mutations is inconsistent (see §5).

## 2. Enumerations

- Role: admin, supervisor, dispatcher, customer_service, billing, tech (OFFICE_ROLES = all but tech, store.tsx:378).
- WOStatus: open, closed (label "Completed"), billed. TechVisitStatus (per block): en_route, on_site, paused, done.
- Priority: urgent, normal, low. CallType: service, maintenance, quoted. billingType: tm, nte, quoted. CallFlag (UI filter): assigned, unassigned, return, parts, warranty. WaitReason (follow-up): parts, quote_sent, approved, return, no_access, warranty.
- QuoteStatus: open, sent, approved, declined, follow_up. QuoteReason: pm, service, customer. QuoteLossReason: price, timing, competitor, no_response, not_needed, other. QuoteFollowUp: quote_sent, approved.
- PoStatus: issued, partial, received, invoiced, cancelled (no action ever sets cancelled). shipTo: work_order, inventory.
- InventoryTxnKind: po_receipt, used_on_wo, transfer_in, transfer_out, count_adjust. Warehouse.kind: main, vehicle.
- Invoice: FrozenInvoice.kind tm|fixed|quoted; FrozenLine.kind labor|travel|material|misc|vehicle|tax|flat; source ""|PO|Truck|Inventory|Direct; taxKind sales|use; InvoiceDelivery email|print|both; CreditReason complaint|incorrect|other; PmBillingMethod pre_billed|on_demand.
- Timesheet line kinds above; BreakReason customer_emergency|waived|forgot|supervisor|other; breakReview.status pending|approved.
- Equipment: UnitSource manual|list_import|nameplate_photo; UnitStage proposed|active.
- Permissions: no scope enum. Two per-user booleans resolved by mayEditCustomers (default admin/supervisor) and mayBill (default admin/supervisor/billing) at store.tsx:1948-1959; otherwise inline role string checks (admin-only: addUser, setCustomerEdits, setBillingEdits, warehouse setup; admin/supervisor: categories, countWarehouse, correctBreak, reviewBreak; +dispatcher: transferInventory; tech limited to own vehicle for inventory POs).

## 3. Features present vs absent

**Supported by model + lib**
- Dispatch: lead/helper/extra-day blocks, visit suffixes (1042-2) via visits.ts, quarter-hour snapping, tech off-days and shiftHours, site primary/backup tech suggestions, follow-up queue with wait reasons/snooze, return visits, in-app TechNotice (assignment/updated), call field-change audit.
- WO lifecycle: open→closed→billed; tech clocks en_route/on_site/paused/done; closeout with workPerformed, canvas **signature** (dataUrl) + signerName + signatureRequired, needReturn; reopen; regex command parser (applyCommand).
- Time: travel/labor split by arrivedAt; per-tech/day Timesheet with meal/rest lines, clock pause/resume around breaks, supervisor meal correction/review, close-day blockers (lunch required). Meal/rest **premium** model exists but detection is hard-disabled (timesheet.ts:313-316).
- Quotes: 20 seeded HVAC scope templates, 3 labor classes, cost+margin pricing, use tax, loss reasons, follow-ups, approve → quoted WO with budgets; quote PDF with company terms/signature page; attached photos/vendor PDFs.
- Purchasing: job or inventory POs, lump vs lined, partial receiving, vendor invoice capture, 15-min lump-sum reminder (LUMP_REMIND_MS), PO PDF, 50-vendor seeded catalog.
- Inventory / **truck stock**: main + per-tech vehicle warehouses, dollar buckets per category, receipts/use/transfer/count, in-out report, activity ledger, count variance; truck parts on WO tied to txns; billing-added "Direct" material.
- Billing: T&M, NTE with over-cap detection, quoted flat, maintenance fixed price via pmContract (pre_billed auto-bills from the 1st; on_demand on close — ensurePmBills), contract vs non-contract margin tables and rates, vehicle charge, misc %, sales vs use tax, tax-exempt, site tax override, invoice numbering, frozen snapshot, revisions with reason, credit memos (line-picked), delivery log (email/print), customer bill + credit memo PDFs, itemized vs one-line layouts.
- Customers/sites/equipment create/update (no delete) with RecordChange audit; account manager; invoice delivery prefs; **multi-company** switch; hand-rolled **XLSX** and **PDF** export.

**Clearly absent**
- Payments, deposits, AR/aging, balance due, payment terms/due dates, refunds (credits only reduce an invoice).
- Maintenance agreement entity, recurring/auto-generated PM visits, memberships/plans (README defers "contracts that spawn work orders"; demo PMs are static rows).
- Customer notifications (SMS/email), customer portal, reviews/surveys — recordInvoiceDelivery only logs; nothing sends.
- Forms/checklists/inspection reports, refrigerant usage logs (EPA 608), warranty entity (boolean + wait reason only), commissions, pricebook/flat-rate catalog, SKU-level parts, GPS/geolocation/mileage/route planning/maps, file storage beyond base64, skills/constraints, accounting/ERP sync (all erpId stay null; erpLaborRates and draftScope are stubs quote.ts:185-195), real auth, deletion/archival, org/team administration, Vendor FK on PO.

## 4. Persistence

- One localStorage key `KEY = "fieldline.db.v4"` (store.tsx:17); entire Db is JSON.stringify'd on every change (1925-1935); storageWarning on quota error. README.md:25 still says v1. No migration between key versions — a key bump abandons prior data. Two ad-hoc one-shot flags: fieldline.clearedAutoBreaks.v2, fieldline.clearedEnRouteTravel.v1 (1743-1744).
- load() (1783-1808): parse → usable() guard (teams non-empty and every WO callType valid, 327-332) else **silent reset to seed**; mergeDemo() re-inserts demo customers/sites/equipment/WOs on every load (1818-1836); legacy fixes (status done→closed, adoptLegacyHelper); then prepare() (1388-1413) runs ~20 idempotent ensure* normalizers (fillBillTo, moveCustomerTechs, ensureCompanyCosts, ensureBills/tidy*, ensureInventory + backfillTruckUses, ensurePmBills…). That normalization pass *is* the migration strategy: no schema version number, no ordered steps. Any JSON exception → catch → seed.
- Seed: seed.ts (org_hcm + empty org_couts, 16 users/11 techs, 4 real sites) + demo.ts (50 customers/sites/units, 140 WOs pinned to 2026-10-06 via a module-level slot allocator), scopes.ts, vendors.ts, inventory.ts seeded warehouses/categories. prepare() also injects 150-dollar "Starting balance" per vehicle×category (1360-1384) and clones a second unit per demo site (421-450). reset() clears KEY and reloads seed (2143-2148).
- IDs: uid(prefix) = prefix + 6 base36 random chars + 3 chars of Date.now (1838-1840) — not UUIDs, not sortable. Business numbers (WO/quote/PO/invoice/credit) = max(existing,1000)+1 in memory; several computed from the stale closure `db` before patch (approveQuote 2422-2439, startVisitQuote 2265, startVisitPo 2314, addPurchaseOrder 2565, reservePurchaseOrder 2596, issuePurchaseOrder 2655).
- Dates: companyDay/companyStamp hardcode America/Los_Angeles (quote.ts:48, 69-93); companyStamp emits "YYYY-MM-DDTHH:mm:ss" with **no offset**, while logs/clocks use new Date().toISOString() (UTC "Z") at store.tsx:1460, 1536, 1544, 1604, 4459, 4468 and all TimeEntry startedAt/stoppedAt. Seed createdAt is UTC-Z, runtime createdAt is companyStamp — one field, two formats — yet code sorts by string compare (visits.ts:127, inventory.ts:277). Day keys are "YYYY-MM-DD" regex-validated; startMinute is minutes from midnight. hoursBetween rounds to quarter hours and adds 24 h when end<=start (timesheet.ts:350-357); clockHoursBetween rounds to 2 decimals (378-383) — two rounding regimes feed billing.

## 5. Architecture observations

- **Routing**: app/page.tsx renders StoreProvider + FieldlineApp; single route, no URLs/deep links; navigation is in-component state with a shared BackBar (.cursorrules). layout.tsx loads Google Fonts via `<link>` (not next/font) and only Apple PWA meta; no manifest, service worker, or public/ dir → not installable on Android/Chrome, no offline queue (README: explicitly out).
- **State**: one Context exposing a ~100-method Store object (interface store.tsx:19-323) rebuilt by useMemo on [db, orgId, userId, role, storageWarning] (4516) — every mutation recreates the API and re-renders all consumers; no selectors, memoized derivations, reducer, or action log. patch(fn) structuredClone()s the whole Db, mutates the draft imperatively, runs ensurePmBills, setState (1940-1947). With base64 photos/PDFs inside Db, each action is O(total data) clone + O(total data) stringify.
- **Derived data**: pure lib functions (workOrderBill, quoteTotals, chargedTime, sheetCheck, inventoryActivity) recompute on demand by scanning whole arrays; applyBillTax runs for every bill on load and ensurePmBills on every patch (O(N×M)).
- **Module boundaries**: lib/* are pure and reasonably layered (billing→timesheet/visits/quote/po). store.tsx is the hub mixing persistence, migrations, seed fix-ups, permissions, domain rules, numbering, notifications, and all actions. types.ts carries many legacy mirror fields the store syncs by hand (defaultTechId/primaryTechId; estimate/contractAmount/quotedAmount; totalHours/laborBudgetHours/allocatedHours; journeymanRate vs costRates; laborRate/vehicleCharge/miscCharge).
- **Tenancy enforcement**: newer actions filter by orgId (quotes, POs, inventory, bills); older ones look up by id only: setStatus 3323, assign 3451, updateCall 3490, setFollowUp 3642, addNote 3863, addTime 3867, addPhoto 3880, addUnit 3233, updateUnit 3261, updateCustomer 3135, updateSite 3196, setTechOff 3310, setShiftHours 3318, setAllocatedHours 3856, addUnitPhoto 4463. Isolation depends on the UI only listing the current org.
- **Authorization**: client-side role from the selected user; setUser lets anyone impersonate; checks are inline and uneven (setStatus "billed" needs no mayBill; applyCommand lets a tech set status billed by typing "billed" at 4480-4486 without creating a Bill/invoiceNumber; addUnit/updateUnit skip mayEditCustomers).
- **Error handling**: validation failures return silently (void/false/""); try/catch only around localStorage; no error boundary; no user-facing error channel.
- **Testing**: none — no test files, runner, or script; tsc strict is the only gate (.cursorrules). billing.ts (896 lines of money/tax math) and timesheet.ts have zero coverage.
- **PDF/XLSX**: fully hand-rolled. pdf.ts writes PDF 1.4 by string concat (Helvetica WinAnsi, fixed 40 lines/page at :36, no horizontal wrapping, chars >255 → "?" at :13-17; only quotes pre-wrap at quote.ts:284). xlsx.ts emits an OOXML zip with hand CRC32, stored entries, inline strings, one currency style, one sheet.
- **Mobile/a11y**: globals.css has 3 media queries (print :540, 640px :545, 980px :1342); signature canvas uses touch-action none; no prefers-reduced-motion, prefers-color-scheme, or focus-visible rules; ARIA not assessable here. structuredClone requires Safari ≥15.4 — older iPhones throw on first action.
- **Scaling to multi-user/backend/offline**: single mutable document, in-memory sequence numbers, no updatedAt/version/ownership on rows, no soft delete, no idempotency; actions are clone-whole/mutate/write-whole, which does not map to row APIs or sync; inline blobs make the ~5 MB localStorage ceiling the real capacity limit; mixed timestamp formats; non-global IDs; migrations are normalizers, not versioned steps.

## 6. Riskiest technical debts

1. Silent total data loss: usable() false (store.tsx:327-332, 1789) or any parse error (1805) resets to seed; KEY bump (17) with no cross-version migration.
2. Hardcoded demo rates overwrite office data: Journeyman bill rate forced to 195/185 on every load (556-557) and every save (2548-2549) — the office can never change it.
3. Seed/demo logic in the production load path: mergeDemo 1818-1836 (demo rows undeletable), hardcoded contacts 1791-1794, keepPlazaCrew 364-376, ensureOfficeUsers 1415-1435 (org_hcm only), ensureScopeTemplates 534-549 (reverts edits; org_hcm only), ensureSecondUnits 421-450, 150-dollar starting balances 1360-1384.
4. Base64 blobs inside the persisted document: types.ts:715, 739, 865, 242-245, 267, 365 with full-DB stringify at store.tsx:1928 and clone at 1942 → quota failures and per-action latency.
5. Whole-API useMemo + clone-per-mutation: 1940-1947, 4516.
6. Weak IDs and stale-closure sequence numbers: 1838-1840; 2265, 2314, 2422-2439, 2565, 2596, 2655.
7. Tenant/permission gaps: lines listed in §5; applyCommand billed bypass 4480-4486; setStatus 3322-3353 without mayBill; addSite creates an orphan site with customerId "" (3114-3132); createWorkOrder spreads raw input into the row (2165).
8. Dead/disabled compliance code: timesheet.ts:313-316 hardcodes missedFirst/missedSecond/missedRest false so applyPremiums/closeTimesheet (store.tsx:4363-4389) never produce premiums; stubs timesheet.ts:333-342, 585-598; noteMissedMeal no-op 4188; PoStatus cancelled unreachable.
9. Timestamp inconsistency: quote.ts:80-93 vs store.tsx:1460, 1536, 1544, 1604, 4459, 4468; string sorts visits.ts:127, inventory.ts:277; hardcoded zone quote.ts:48; dual rounding timesheet.ts:350-357 vs 378-383.
10. Zero tests for money/time math; README.md stale (:25 key v1; :40 "Explicitly out" contradicts shipped inventory/quoting/procurement/billing; :45-54 schema/roles outdated).
11. Monoliths: store.tsx 4,531 lines; components/FieldlineApp.tsx 10,511 lines / 556 KB (size only).
12. Hand-rolled PDF has no wrap/overflow handling (pdf.ts:36, 45-58) and loses non-Latin characters (13-17).
